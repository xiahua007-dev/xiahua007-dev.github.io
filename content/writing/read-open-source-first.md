## 写作方向

读一个开源项目时，第一步不是马上进入某个函数，而是先判断项目解决的问题、面向的用户和工程边界。

这篇文章会整理一套可复用的阅读顺序，让源码学习更像工程分析，而不是随机浏览。

## 计划覆盖

- 从 README 和发布包判断项目定位
- 从目录结构识别模块边界
- 从构建、测试、CI 理解工程约束
- 从 issue、PR 和 changelog 观察真实演进
